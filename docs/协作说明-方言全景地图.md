本文档用于同步 **前端地图页、Mock 接口、后端联调结构与状态枚举**。当前版本已经从“点位展示 + 上传弹窗”升级为“方言数据生产系统前台”。

## 2. 状态与视觉语义

### 2.1 地图图层

公共地图与工作台地图共用 3 个图层：

| `layer` | 标签 | 含义 |
|--------|------|------|
| `new` | 新贡献 | 刚进入系统，尚未完成治理启动 |
| `processing` | 治理中 | 正在被清洗、转写、标注、质检，含 `review` 子状态 |
| `ready` | 可训练 | 已完成治理，可进入训练语料库 |

### 2.2 样本状态

| `status` | 对外展示 | 说明 |
|---------|---------|------|
| `new` | 新贡献 | 收录中或等待进入治理链路 |
| `processing` | 治理中 | 主流程自动推进中 |
| `review` | 需复核 | 命中低置信度或失败节点，公共层仍视作 `processing` 图层 |
| `ready` | 可训练 | 可进入训练语料库 |

### 2.3 公开治理主阶段

顺序固定，不建议私自改名：

1. `ingest` / 收录
2. `clean` / 清洗
3. `transcribe` / 转写
4. `annotate` / 标注
5. `qa` / 质检
6. `archive` / 入库

### 2.4 内部节点

内部节点目前固定 8 个：

1. `geo-normalize` / 地理归一
2. `denoise-vad` / 降噪 / VAD
3. `asr` / ASR
4. `dialect-id` / 方言识别
5. `segment` / 切分
6. `normalize-text` / 文本规范化
7. `safety-check` / 去重脱敏 / 授权检查
8. `human-review` / 人工复核

每个阶段 / 节点的 `state` 允许值：

- `waiting`
- `running`
- `complete`
- `failed`
- `review`

## 3. 接口约定

### 3.1 公共总览

- **方法 / 路径**：`GET /api/map/overview`

```json
{
  "code": 0,
  "data": {
    "totalContributions": 1284,
    "processingCount": 328,
    "readyCount": 812,
    "newCount": 91,
    "reviewCount": 53,
    "regionCoverage": 287,
    "newLast24h": 41,
    "readyRate": 0.632,
    "highlightSentence": "每一段乡音，都有坐标、状态与去向。"
  }
}
```

### 3.2 地图点位

- **方法 / 路径**：`GET /api/map/points`
- **查询参数**：

| 参数 | 说明 |
|------|------|
| `layer` | 必填，`new | processing | ready` |
| `province` | 可选 |
| `city` | 可选 |
| `district` | 可选 |
| `type` | 可选，多值时用逗号分隔 |
| `status` | 可选，精确过滤内部状态 |

```json
{
  "code": 0,
  "data": [
    {
      "id": "seed-001",
      "location": { "lng": 120.153576, "lat": 30.287459 },
      "area": "浙江省/杭州市/西湖区",
      "dialectLabel": "吴语·杭州小片",
      "type": "方言",
      "status": "new",
      "audioUrl": "./video-stitch/wenzhou/wenzhou-001.m4a",
      "transcriptSnippet": "",
      "qualityScore": null,
      "readySegmentCount": 0,
      "createdAt": "2026-06-08T..."
    }
  ]
}
```

### 3.3 创建贡献

- **方法 / 路径**：`POST /api/contributions`
- **Content-Type**：`multipart/form-data`

| 字段 | 必填 | 说明 |
|------|------|------|
| `file` | 是 | 音频文件 |
| `area` | 是 | `省/市/区县` |
| `dialectSelfReport` | 是 | 用户自报方言 |
| `type` | 是 | `方言 / 戏曲 / 民谣 / 童谣 / 民俗` |
| `content` | 否 | 场景说明或文字补充 |
| `nickname` | 否 | 展示昵称 |
| `consentGranted` | 是 | 必须为字符串 `true` |

成功返回：

```json
{
  "code": 0,
  "data": {
    "id": "1749320000000",
    "point": {
      "id": "1749320000000",
      "area": "浙江省/杭州市/西湖区",
      "status": "new"
    }
  }
}
```

前端行为：

- 上传成功后立即切到 `workbench`
- 自动选中该样本并打开追踪卡
- 下一轮轮询中样本会从 `new` 推进到 `processing`，最终进入 `ready`

### 3.4 单条贡献详情

- **方法 / 路径**：`GET /api/contributions/:id`

附加字段：

| 字段 | 说明 |
|------|------|
| `dialectSelfReport` | 用户自报方言 |
| `nickname` | 昵称 |
| `content` | 上传说明 |
| `consentGranted` | 授权状态 |
| `reviewReason` | 需复核原因 |
| `riskFlags` | 风险标签数组 |
| `nextAction` | 当前建议动作 |

## 5. 后端推荐模型

当前前端与 Mock 已按以下逻辑组织，真实后端建议映射到这些表：

| 表名 | 说明 |
|------|------|
| `contributions` | 样本主表，记录地区、方言自报、类型、状态、授权等 |
| `media_assets` | 原始音频与衍生文件 |
| `pipeline_jobs` | 主阶段与内部节点的运行记录 |
| `corpus_segments` | 可训练分段、文本、标签、质量分 |
| `review_tasks` | 仅在低置信度 / 风险 / 失败时创建 |

说明：

- `review_tasks` 不属于主流程表，而是异常分流表。
- `status=review` 时，公共地图仍归入 `processing` 图层。

## 6. 兼容与过渡

### 6.1 保留旧接口

兼容期保留：

- `POST /api/map/upload`

用途：

- 旧代码仍可走老字段 `dialect`
- Mock 中会自动映射到新贡献结构，并默认 `consentGranted = true`

### 6.2 不再推荐的旧字段

以下旧字段已不再作为主接口约定：

- `dialect`
- `time`
- 旧详情卡仅依赖的 `nickname / content / audioUrl` 组合

请新代码统一使用：

- `dialectSelfReport`
- `createdAt`
- `status`
- `transcriptSnippet`
- `qualityScore`
- `readySegmentCount`
- `riskFlags`
- `nextAction`

## 7. 联调注意点

1. 前端会轮询 `overview + points + metrics + selected contribution detail/pipeline`，周期固定 6 秒。
2. 地图页初始永远落在 `public`，不是工作台。
3. 上传必须要求授权同意，否则前端会直接阻止提交，Mock / 后端也会返回 400。
4. 地图空白点击会选中当前图层内最近点位，距离阈值约 280 km。
5. 当前聚类逻辑在前端完成，后端只需返回点位，不需要先做瓦片聚合。
6. 若真实后端改用 SSE，请保留现有字段形状，前端可以在不换视图结构的情况下切换。
